# 第二课讲义：Token、Embedding 与位置信息

第一课把文字变成数字，再用 Attention 混合信息。本课补上输入端的三个问题：切分规则从哪里来？向量怎样得到？顺序怎样进入计算？

## 一、文本如何变成 token，为什么这样切分？

### 字、词和子词是不同的选择

“我喜欢喝牛奶”有六个汉字，可以按字表示，也可以按“我 / 喜欢 / 喝 / 牛奶”作一种词切分。

按字切，基础单位较细，序列可能较长。只用完整词，词表可能膨胀，且遇到未收录的新词时难以直接处理。子词方法复用较小片段，兼顾覆盖与长度；token 可以是字、词的一部分，甚至是跨越人类词边界的片段。token 数不能由汉字数固定换算。

### BPE：学习一份合并规则，再用它切文本

本课小语料：

| 句子 | 次数 |
| --- | --- |
| 我喜欢喝牛奶 | 5 |
| 你喜欢喝牛奶 | 3 |
| 我喜欢喝酒 | 2 |

从字符列表开始，统计相邻片段在语料里的加权频次。选一对高频片段合并，更新各句的当前片段，然后重新统计。本例选择四轮合并：

| 轮次 | 合并 | 该轮频次 |
| --- | --- | --- |
| 1 | 喜 + 欢 → 喜欢 | 10 |
| 2 | 喜欢 + 喝 → 喜欢喝 | 10 |
| 3 | 喜欢喝 + 牛 → 喜欢喝牛 | 8 |
| 4 | 喜欢喝牛 + 奶 → 喜欢喝牛奶 | 8 |

首轮“喜+欢”和“欢+喝”同频，本例按首次出现次序打破并列。规则学好后固定下来，使用时不根据当前句子重新训练：

```text
我喜欢喝牛奶 → 我 / 喜欢喝牛奶 → [4,11]
我喜欢喝酒   → 我 / 喜欢喝 / 酒 → [4,9,7]
```

“喜欢喝牛奶”合成一个 token，不表示这是正确的中文词语划分；它只是这份小语料和规则的结果。实际 BPE 还需处理预切分、边界、特殊符号等细节。WordPiece、Unigram 也是子词方法，不能把所有 tokenizer 都等同于本例 BPE。[BPE 原论文](https://aclanthology.org/P16-1162/)

### 字符、字节与最终 token

UTF-8 中，“牛奶”是两个汉字、六个字节。某些 tokenizer 从字节或带字节回退的单位出发，再把基础单位合并，所以六个字节不等于六个最终 token。

本课字符级词表只覆盖八个基础字符；遇到“咖啡”等新字符，不能自动查到 ID。完整字节覆盖有助于处理任意有效文本，但实际能否还原原字符串，还取决于是否有小写化、去音调等有损规范化，以及特殊符号的处理。预处理、预切分、模型规则和后处理都属于 tokenizer 配置。[Tokenizer 流水线](https://huggingface.co/docs/tokenizers/pipeline)

## 二、token 如何变成 embedding，为什么这样映射？

### ID 是地址，embedding 是参数

ID 的大小和差值没有天然的语义含义。ID=4 不意味着比 ID=11 更小或更接近另一种词义。

令词表大小为 V，向量维度为 D，embedding 表 E 的形状是 `[V,D]`。输入一个 ID，取对应行：

```python
vectors = [table[token_id] for token_id in token_ids]
```

本课 V=12、D=4。输入 `[4,11]` 取两行，得到 `[2,4]` 的向量列表：

```text
4  我           → [ 0.127, 0.448, 0.077, −0.103]
11 喜欢喝牛奶   → [−0.256, 0.074, 0.025,  0.375]
```

这只是固定随机种子的初始化结果，没有训练好的词义。真实模型的表行会参与训练。查表是 embedding 层的基本接口。[PyTorch Embedding](https://docs.pytorch.org/docs/stable/generated/torch.nn.Embedding.html)

### 为什么不直接用整数或 one-hot？

直接把 ID 当数值，容易给类别编号强加本不应有的数值关系。one-hot 用 V 个位置区分类别；它与 embedding 的关系是：one-hot 乘以 E，等价于选出 E 的相应行。

查表不必显式创建 V 维 one-hot。D 可以独立于 V 选择，并常常远小于 V，后续网络都在共同的 D 维接口上计算。表本身仍有 V×D 个参数，不能说用了 embedding 就不需要存大表。

稠密向量为 token 提供可调整的特征，让训练决定怎样表示才有助于任务。它不保证每个近义词都相邻，也不保证某一维就是固定的人类概念。若同时重新编号并相应重排表行，查出的向量可以完全不变；只改编号、不改表行，则会错配。

### 数值从哪里学来？

先初始化，计算任务的预测和误差，再通过参数更新让误差减小。语言模型会学习输入 embedding、各层投影等参数。本课的独立更新实验只训练四个 token 的二维表，让“酒、牛奶”配“喝”，“苹果、香蕉”配“吃”：

```text
平均交叉熵：0.6981 → 0.0656
```

这是实际执行的参数更新，但任务是小型分类，不是完整的下一 token 预训练。数值改善只说明这四个训练样本的拟合更好。不要把它与主线 12×4 的随机表混为一套模型。

参数固定时，同一 ID 查到相同的输入 embedding。加入位置并经过 Transformer 后，隐藏表示可以随上下文变化。“输入查表固定”和“上下文表示可变”并不矛盾。

## 三、模型怎样获得位置信息？

### 行序存在，不等于运算已经利用了位置

输入矩阵有行序；但无位置机制、无遮罩的标准 self-attention 对重排是等变的：输入重排，输出相应重排。仅靠内容向量不会凭空产生绝对位置或前后关系特征。这里的条件很重要，不能把它套到带因果遮罩的所有计算上。

### 相加式绝对位置表示

为 token 位置 p 构造与 embedding 同维的位置向量：

```text
x[p] = E[token_id] + P[p]
```

同一个 token 的内容向量可以相同，而位置不同，组合后的输入不同。位置 p 是切分后的 token 位置，不是原文字符偏移；本例六个汉字切成两个 token，就使用位置 0 和 1。相加后形状保持 `[T,D]`，不要求把内容和位置从和向量中无损拆开。

位置向量可以学习：准备一张 `[L,D]` 的位置参数表，按当前位置 p 查行，再与内容向量相加；可直接查表的范围受位置表长度 L 限制。也可以用固定公式计算。原始 Transformer 使用不同频率的正弦、余弦编码：[原论文 §3.5](https://arxiv.org/html/1706.03762v7)

```text
PE(p,2i)   = sin(p / 10000^(2i/D))
PE(p,2i+1) = cos(p / 10000^(2i/D))
```

D=4 时，两对维度的角度分别是 p 和 p/100：

| 位置 | 四维位置编码（显示值） |
| --- | --- |
| 0 | [0, 1, 0, 1] |
| 1 | [0.8415, 0.5403, 0.0100, 1.0000] |
| 2 | [0.9093, −0.4161, 0.0200, 0.9998] |

将“我”的向量 `[0.127,0.448,0.077,−0.103]` 放到位置 0 和 2，组合结果约为 `[0.127,1.448,0.077,0.897]` 与 `[1.0363,0.0319,0.0970,0.8968]`。保留原始精度运算，只在展示时舍入。

### 遮罩、绝对位置与 RoPE

| 机制 | 改变什么 | 作用 |
| --- | --- | --- |
| 因果遮罩 | 可见位置的范围 | 防止读取未来输入 |
| 绝对位置相加 | 进入网络的表示 | 提供位置索引信号 |
| RoPE | Q/K 成对维度的旋转 | 让旋转点积体现相对位移 |

RoPE 不等于把位置数字直接加到 token ID 或原始 embedding 上。其二维旋转点积在同时平移 Q/K 位置、保持相对位移时不变；这只是一项局部代数性质。[RoFormer](https://arxiv.org/abs/2104.09864)

“提供位置信息”意味着让模型能够利用顺序信号，并不保证它在所有句子中都正确理解顺序。正弦公式可计算更大的索引，也不自动保证更长上下文上的效果。
