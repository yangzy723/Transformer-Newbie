# 第二课教案：Token、Embedding 与位置信息

## 课程信息

**授课对象**：完成第一课，会运行 Python 列表、循环和函数的同学。**课时**：60 分钟。

教学目标：

1. 解释 BPE 的训练与使用，说明切分不必符合人类词语边界。
2. 根据 token ID 查 embedding 表，说明编号、参数与训练的关系。
3. 用同一个 token 的不同位置实验，解释顺序信号如何进入计算，并区分遮罩与位置机制。

重点是每段的输入、输出和参数来源。BPE 的完整统计实现、梯度推导和 RoPE 多维公式不要求掌握。

## 课前准备

- 打开 [18 页 PPT](class2_tokens_embeddings_positions.pptx)、[课堂 Notebook](demo.ipynb)、[课程地图](course_map.md)。
- 执行三个主线脚本；确认查表得到 ID 4 和 11 的四维向量。
- 执行 `optional/train_bpe.py` 与 `optional/embedding_update.py`，课堂只展示关键输出。拓展 Notebook 为 [experiments.ipynb](optional/experiments.ipynb)。
- Notebook 若不能启动，直接运行 Python 脚本；[运行记录](sample_run.md)可作备份。课堂不安装包。

## 0–5 分钟｜回顾与三个问题（PPT 1–2）

**0–3，第 1 页**：写“我喜欢喝牛奶”，不加空格。问：“第一课用空格切了词，现在没有空格，应该怎么切？”

接着问：“切完的编号为什么能查成向量？同一句话里的第一个、第二个位置又在哪里体现？”让同学画 `文字 → ID → 向量 → Attention`。

**3–5，第 2 页**：给出本课三段地图。告知今天只研究 Attention 之前的输入表示，仍然用小词表、短代码和四维向量。

## 5–20 分钟｜一、文本到 token（PPT 3–6）

### 5–8，第 3 页：为什么不固定按字或按整词？

运行 Notebook 单元 1。六个汉字按字得到六项，按一种词切分得到四项。问：“这两种方法分别会遇到什么问题？”

讲清：单位越细，常使序列更长；完整词表需要收录大量词，遇到新词时难以直接覆盖。子词复用较小片段，在词表规模、覆盖与长度之间折中。不要说所有模型都采用 BPE，也不要给出固定的汉字/token 换算。

### 8–12，第 4 页：合并规则怎样得到？

写三行语料与次数：我喜欢喝牛奶×5、你喜欢喝牛奶×3、我喜欢喝酒×2。

让同学数“喜+欢”：5+3+2=10。“欢+喝”也是10，本例按首次出现顺序选择前者。合并后，原来的字符列表变成当前片段列表，再统计下一轮。

运行 `python3 class2/optional/train_bpe.py`，看四轮输出：10、10、8、8。强调停止四轮是本例词表规模的选择，不把“频次最高”解释成“语言学上最合理”。

### 12–16，第 5 页：使用已有规则，不重新训练

运行单元 2、3。合并函数只做一件事：从左到右扫描，遇到指定相邻对就合并。观察“我 / 喜欢喝牛奶”，再查词表得到 `[4,11]`。

提问：“喜欢喝牛奶是一整个自然语言词吗？”预期：不是。切分来自本例语料与算法；tokenizer 不需要先理解整句话。

若改输入“我喜欢喝酒”，固定规则会得到“我 / 喜欢喝 / 酒”，ID `[4,9,7]`。课堂可先口头预测，课后再改代码；使用阶段不把新输入加入统计重学。

### 16–20，第 6 页：字符、字节与配置

运行单元 4，“牛奶”的字符数为2、UTF-8字节数为6。问：“因此它一定有六个 token 吗？”预期：不一定，基础单位仍可能合并。

说明实际 tokenizer 还受规范化、预切分、特殊符号和词表规模影响。本课只覆盖列出的八个基础字符，“咖啡”不在其中，不能直接查 ID；不要现场输入未知字符后把报错误解为 BPE 的普遍限制。

有完整字节覆盖的实现能处理更多文本，但有损规范化可能丢失原始字符串信息。只要求区分“字符、字节、最终token”。

## 20–38 分钟｜二、token 到 embedding（PPT 7–11）

### 20–23，第 7 页：编号不是语义

问：“ID=4 与 ID=11 的差7，是否说明它们语义距离为7？”预期：不是。编号像表的地址，换编号并对应重排表行，查出的向量可以不变。

用 one-hot 的一个“1”解释选行，one-hot 乘 embedding 表等价于取某行。无需创建大 one-hot，也无需展开矩阵乘法证明。

### 23–27，第 8 页：运行查表

运行单元 5。词表12项、每行4维，输入 `[4,11]` 输出两行四维向量。请同学指出“我”的一行：

```text
[0.127,0.448,0.077,−0.103]
```

说明这是固定种子的随机初始化，不是训练结果，不给每一维指定语义。表中其他行也存在，只是本次只读两行。

### 27–31，第 9 页：为什么采用稠密、可学习的向量？

对照 ID、one-hot、embedding：ID是地址；one-hot标识类别；D维表行提供可训练特征，使后续网络使用同一维度接口。D不必等于词表大小V，表的参数量仍为V×D。

强调语义关系是训练的结果之一，不是查表操作自动赋予的性质；也不保证近义词一定相邻。

### 31–35，第 10 页：观察一次真实参数更新

运行 `python3 class2/optional/embedding_update.py` 或拓展 Notebook 第2单元。四个 token 分为“配喝 / 配吃”，只训练二维 embedding 表，输出层固定。

让同学比较更新前后表行，再看平均交叉熵约从0.6981降至0.0656。说清三步：查表预测、算误差、更新参数。可以指出更新行，但不推导梯度。

此实验是四行二维表，与主线十二行四维表不同；只能说明小型分类任务拟合改善，不宣称学到了完整语言知识。

### 35–38，第 11 页：输入表行与上下文表示

运行单元 6，再次查“我”，输入 embedding 相同。问：“这是否意味着我在所有句子里的模型表示都一样？”预期：不是，经过位置与上下文计算的隐藏表示可以改变。

这里假定模型参数固定；训练会改变表。词表、ID和表行配套，不能随意替换 tokenizer 却继续沿用原表地址。

## 38–53 分钟｜三、位置信息（PPT 12–15）

### 38–42，第 12 页：顺序为什么需要进入运算？

先问：“输入列表明明有先后，为什么还需要位置机制？”

澄清：行序存在；但无位置、无遮罩的标准 self-attention 对重排是等变的，输入重排只会使输出对应重排，不能仅从内容产生绝对位置或前后关系特征。这一说法有“无遮罩”的条件，不能忽略因果mask带来的可见结构变化。

不要求背术语，让同学理解位置需要以一种可参与计算的方式给模型。

### 42–46，第 13 页：相加式位置表示

板书 `x[p]=E[id]+P[p]`。内容回答“是什么”，位置向量由token位置决定。两个四维向量相加，结果仍四维。

位置从0开始，针对token，不针对原文字符。六个汉字在本例只切出两个token，所以实际输入只用位置0和1。可学习的位置表按p选行，可直接使用的索引受表长限制；也可以固定公式计算位置。相加只是其中一类方法，不要求把和向量无损分解回原来的两部分。

### 46–50，第 14 页：运行正弦位置编码

运行单元 7、8。D=4 时两组角度是p和p/100，用sin、cos填成四个数。

位置0为 `[0,1,0,1]`，位置2约为 `[0.9093,−0.4161,0.0200,0.9998]`。同一个“我”与二者相加，组合结果不同。

让同学回答哪些量变了：原token向量没变，位置编码与组合输入变了。保留原始精度计算，仅展示时舍入。这个实验检验输入信号变化，不证明模型已正确理解所有词序。

### 50–53，第 15 页：位置、遮罩与 RoPE

用三行对照：mask限制可见范围；相加式位置编码改变输入；RoPE按位置旋转Q/K，使旋转点积体现相对位移。mask与位置机制可以配合，不相互替代。

本课不展开多维RoPE公式。课后运行二维验证脚本，相对位移同为2的两组位置有相同旋转点积。正弦能计算更大索引，或RoPE有相对位移性质，都不等于完整模型保证无限外推。

## 53–56 分钟｜连接整条输入链路（PPT 16）

运行 Notebook 单元9，使用实际切分结果查ID和表行，再组合位置。核对：6个汉字 → 2个token → `[4,11]` → `[2,4]` 的输入。

这里按相加式位置机制组合。若使用RoPE，位置会在后续Q/K处引入，不把所有架构都画成固定的E+P。

## 56–60 分钟｜检查与作业（PPT 17–18）

**56–58，第17页**：同学自己回答：为什么本例合并“喜欢喝牛奶”？为什么ID差值没有天然语义？同一个token换位置时什么会变？答错就回到对应输出。

**58–60，第18页**：布置三个实验：换输入而保留规则、重编号并对应重排表、保持内容只改位置。约20分钟，参考答案在 [练习页](exercises.md)。

| 情况 | 处理 |

| 不懂梯度 | 只观察误差与参数确实变化，不补反向传播推导 |
