# 第二课教案：Tokenizer、Embedding 与位置机制

**60分钟，20页。** 对象：会一点Python、完成第一课、认识Q/K/V的同学。

正文按“机制解释 → 完整数值算例 → 关键代码”组织。先读 [授课主线](teaching_story.md)，切换实验时查 [知识代码对照](knowledge_code_map.md)。

## 课前准备

安装依赖，运行 `python class2/code/worked_examples.py` 和 `python class2/tools/check_experiments.py`。打开PPT和已执行的Notebook。准备单元与12个实验保持对应；配置使用本地320项JSON。

奶茶/咖啡的字符级BPE用于讲规则，真实ByteLevel仍以“我喜欢喝牛奶。”为主例。算术小表的ID与真实词表ID分开。课堂不讲词表320/384的token数量对比。

统一记号：$I$为ID，$\mathbf{E}$为参数表，$t$为位置，$\omega_i$为频率，$\theta_{t,i}=t\omega_i$为角度。行置换用$\Pi$，概率向量用$\mathbf{p}$。


## 0–3 分钟｜第1页：文本怎样成为模型输入？

- 语言模型预测的是下一个 token；本课先解决文本怎样进入模型。
- 文本先按固定规则得到 ID；ID 再读取可训练参数，成为向量。
- 同一 ID 在不同位置仍读取同一行，因此还要让位置参与计算。

**授课操作与提醒**：沿用第一课的Q/K/V概念，新增B、T、D、V四个形状符号。本课有字符级BPE机制实验与真实ByteLevel BPE实现，两者的词表和ID不混用。课堂运行已保存的本地配置，不下载预训练模型。准备阶段安装Tokenizers与PyTorch。

## 3–6 分钟｜第2页：分得更细，还是词表更大？

- 按字：片段短、组合灵活，但同一段文本通常需要更多 token。
- 按整词：序列可能更短，但词表更大，新词也更难处理。
- BPE 在基础单位之上合并常见片段，复用已有片段表示新组合。

**授课操作与提醒**：只计算单个embedding矩阵，32768×4096×2字节=256MiB；未绑定的输出权重另占一份。注意力分数矩阵的T²描述稠密实现，不能说整个模型成本仅由T²决定；logits投影也有T×D×V成本。更大的词表不保证所有文本都更短，本页仅用手工切分比较粒度，不再讲词表320/384的数量对比。

## 6–10 分钟｜第3页：BPE：先统计，再合并

- 演示语料：我喜欢喝奶茶×5、你喜欢喝奶茶×3、我喜欢喝咖啡×2。
- 第一轮“喜+欢”频次为5+3+2=10；“我+喜”只有5+2=7。
- 先合并喜+欢，再重新统计；四轮依次得到喜欢、喜欢喝、喜欢喝奶、喜欢喝奶茶。

**授课操作与提醒**：打开bpe_core.train_bpe，解释corpus中的频次乘数。首轮喜+欢与欢+喝同为10，本例按首次出现顺序打破并列。边界由预切分决定，本字符示例把每句作为一个片段；真实库下一页展示正则预切分。讲清训练不是梯度下降，而是统计和贪心合并。 演示语料改为奶茶与咖啡，四轮频次仍为10、10、8、8。

## 10–14 分钟｜第4页：BPE 编码：谁的 rank 更小？

- 固定上一页学到的四条 merges，对“你喜欢喝奶茶”逐轮执行。
- 编码时不再统计训练语料，也不更新 merges，只选择当前候选的最小 rank。
- 遇到重叠候选时，优先级比片段长度重要；abc 的反例得到 a/bc。

**授课操作与提醒**：用语料bc×6、ab×5、abc×1训练两轮，先bc频次7，再ab频次5。词表含ab、bc，但编码abc按rank得到a/bc，最长前缀会得到ab/c。运行bpe_core.demo看反例，再指出encode_bpe每轮枚举当前相邻候选并选最小rank。真实实现常用更高效数据结构，本课重在规则语义。 先走完奶茶例子的四步编码，再用abc说明重叠候选为何不能最长匹配。

## 14–18 分钟｜第5页：把 BPE 接到真实文本上

- 字符演示说明合并规则；真实库还要处理文本边界、基础字节和解码。
- 本课 ByteLevel 用完整256字节字母表覆盖UTF-8字节，并设置4个特殊符号。
- 保存的不只是词表，还包括merges、预切分和decoder；之后加载完整配置。

**授课操作与提醒**：展示train_tokenizer.py中的Tokenizer(BPE)、ByteLevel、BpeTrainer和save。设置完整256字节基础字母表，四个特殊token，目标词表320或384。不设置有损normalizer，add_prefix_space=False。本地语料28行，重复10遍用于频次。已提交配置用于课堂复现，现场不必重训。不能把该小语料tokenizer称为商用模型的预训练配置。

## 18–20 分钟｜第6页：ID 必须与参数表配套

- 默认配置把“我喜欢喝牛奶。”编码为[300,304,262]，这些ID是参数表的行地址。
- 另一份同样大小的词表，也可能给同一片段分配不同ID，直接替换会读错参数。
- bos/eos由本课batch代码显式加入；pad=0只用于补齐，不代表真实文本。

**授课操作与提醒**：展示assets/tokenizer_320.json及384版本。ByteLevel与decoder让普通测试文本完整回解；skip_special_tokens默认会处理特殊符号，不能据普通文本测试承诺所有特殊字符串也逐字可逆。配置改变时须同步参数映射，不能直接拿320模型的embedding套384词表。

## 20–24 分钟｜第7页：Embedding：一个 ID 选择一行

- 查表等于用one-hot选择一行，既保留可学习参数，又避免显式分配大one-hot张量。
- 算术小表中，ID=[1,2,1]会读到第1行、第2行、再读一次第1行。
- 行向量最初可以随机初始化；训练任务逐步调整它们，每一维没有预先规定的语义。

**授课操作与提醒**：运行embeddings.py的前半段，torch.allclose(lookup,one_hot@E)为True。真实示例E为[320,8]，batch为[2,6]，X为[2,6,8]。one-hot只为验证构造，不建议大词表训练时这么实现。对应重编号并重排行能保持前向结果不变。

## 24–27 分钟｜第8页：不同长度，怎样组成 batch？

- 第一句3个普通token加bos/eos得5项；第二句4个加标记得6项，因此前者补1个pad。
- 补齐只统一张量形状；Attention仍应屏蔽pad key，训练loss仍应忽略pad标签。
- padding_idx抑制lookup路径的pad行梯度，不会替后续网络自动处理mask。

**授课操作与提醒**：make_batch手动加bos/eos；第一句长度5，第二句长度6，第一句末尾补pad。nn.Embedding默认将padding行初始化为0并在lookup反传中抑制其梯度；加载或手动改值时不要假定它永远为0。Attention的padding key mask以及交叉熵ignore_index各自仍要处理。

## 27–31 分钟｜第9页：读了同一行，梯度就要相加

- 把同一行看成被多处引用的共享参数；每个位置贡献自己的向量梯度。
- 若ID1两次上游梯度为[1,0]和[0,2]，第1行收到[1,2]，不是取平均也不是覆盖。
- 求和损失只是特殊情况：上游全为1，出现两次的行每一维梯度为2。

**授课操作与提醒**：运行embeddings.py后半段，用.sum().backward()明确上游每维梯度是1；a出现两次所以对应行每维2，b每维1，padding lookup为0。这是诊断loss，不是语言模型交叉熵。未用作输入的行在此lookup路径梯度为0；绑定输出权重或施加weight decay时不能把它说成所有训练情形的更新规律。

## 31–34 分钟｜第10页：预测误差怎样传回向量？

- 类别编号0/1/2，目标y=1，预测p=[0.1,0.7,0.2]；交叉熵为−ln(0.7)≈0.3567。
- 类别误差p−one_hot(1)=[0.1,−0.3,0.2]，右乘输出权重得到输入向量梯度。
- 小算例得到[-0.1,-0.2]，与autograd一致；真实词表只是把类别数扩到V。

**授课操作与提醒**：W_out形状[V,D]，p-y是[V]，右乘得到[D]梯度。写一个正确类别的p_y低时误差大的例子，不推导softmax完整Jacobian。公式按单个位置；实际batch mean loss还包含平均因子。F.cross_entropy直接接原始logits，内部完成log_softmax，不先softmax。

## 34–37 分钟｜第11页：让 Embedding 真正学一次

- 把相邻token构成(x,y)：当前ID查表，经Linear产生所有候选的logits，再与真实下一ID比较。
- 每步依次前向、清梯度、backward、optimizer.step；梯度负责指出如何调整参数。
- 本例只利用当前token；同一token可能有多个后续，所以训练loss不必降到0。

**授课操作与提醒**：运行embedding_train.py或Notebook训练单元。模型只用当前token预测下一项，因此是bigram基线，不是Transformer；同一个输入可能有多个后续，loss不必归零。无验证集，仅观察训练拟合。在无weight decay、未绑定输出权重的本实验中，更新行数26与出现过的输入行数一致。 本数据仅依赖当前token时的经验条件熵下界约0.35583；此项供老师解释loss平台，不要求课内计算。训练pair未补齐，不含pad标签。

## 37–39 分钟｜第12页：一张表，两条梯度路径

- 不绑定时，输入E与输出W是两个参数；绑定后输出直接使用E的转置。
- 输入查表只读取少数行，输出softmax却把全词表作为候选，因此更多行可能收到梯度。
- padding_idx只限制lookup路径；绑权重并不保证pad行完全没有梯度。

**授课操作与提醒**：本课bigram代码未绑定，便于先看lookup行更新。若绑定，词表全体候选参与输出softmax，未作为输入的行也可能收到输出梯度；padding_idx只限制lookup路径。设置output.weight=embedding.weight应在创建optimizer之前完成，并用去重的参数迭代器。相似度受训练任务影响，不能把每维解释为固定语义标签。

## 39–42 分钟｜第13页：没有位置，重排会怎样？

- “我/喜欢/你”换成“你/喜欢/我”，仅查表得到的仍是同一组内容向量。
- 无位置、无mask时，Q/K/V随行重排，scores行列同时重排，输出也对应重排。
- 因果mask带有可读范围约束，不满足这里任意置换的假设；等变不等于输出不变。

**授课操作与提醒**：给出三行token的重排，说明输出随行重排，而非整个矩阵不变。运行position_mechanics.py：无位置时True，给新行位置加PE后False。不要求证明任意网络性质，只连接QK转置和softmax逐行对称性。因果mask并不随任意置换同样改变，所以不满足这里的假设。 用 Π 记行置换，与学习式位置表 P 区分。

## 42–45 分钟｜第14页：把位置向量加进输入

- 内容向量表示“是什么”，位置向量提供“在第几个token”；相加后仍是D维。
- 学习式位置表通过训练更新，直接查询范围受表长L限制；正弦编码由固定函数生成。
- 相加式位置与RoPE是不同接口，本课RoPE分支不先叠加绝对位置。

**授课操作与提醒**：不要把BPE的字符offset当成token位置。可学习位置表也参与反向传播；正弦表不需要训练其数值。相加式输入与RoPE是不同接口，下一页分别说明，代码不会先加绝对PE又声称相对旋转分数必然保持不变。

## 45–48 分钟｜第15页：位置 × 频率，得到角度

- D=4时有两对维度，频率分别为1和0.01；同一位置形成两种变化尺度。
- t=1时角度为[1,0.01]，分别取sin/cos并交错排列，得到4维位置向量。
- 广播[T,1]×[1,D/2]生成全部角度；能计算更远位置不等于模型一定能泛化。

**授课操作与提醒**：D=4时频率1与0.01，沿用上一版四维数值核对。多个频率提供不同变化尺度，单一周期不能代替全部设计。指出pos[:,None]*frequencies[None,:]的广播形状[T,D/2]，而非逐token循环。可计算更大p不等于模型长上下文质量有保证。 统一记号：ω_i 为频率，θ_{t,i}=tω_i 为角度；分别对应 frequencies 与 angles。

## 48–51 分钟｜第16页：RoPE：相对位移从哪里来？

- 一对维度用二维旋转R；转置相当于反向旋转，两次旋转的角度相加。
- q、k按mω、nω旋转后，点积里出现(n−m)ω，因此相对位移影响分数。
- 二维算例m=1,n=3,q=k=[1,0]得到cos(2)≈−0.4161；两位置同时加5结果不变。

**授课操作与提醒**：从二维旋转矩阵的转置等于反向旋转、旋转可相加讲到相对位移，约两步，不展开所有矩阵项。保持未旋转q/k不变、同时平移位置时点积不变；完整模型的q/k可能随上下文变化，所以不推出任意平移文本模型输出不变。

## 51–54 分钟｜第17页：把二维旋转写成两行代码

- 把相邻维度分成even/odd两组，分别实现旋转矩阵的两个分量。
- Q/K形状[B,H,T,d_h]，角度[T,d_h/2]广播到batch和head，旋转后形状保持。
- 相邻配对与split-half是不同坐标约定；本实现只旋转Q/K，不旋转V。

**授课操作与提醒**：展示positions.apply_rope。使用相邻维度配对，另一种split-half实现需有一致的坐标排列；不混用两种配对约定。函数支持[...,T,D]，D必须为正偶数。运行整体位置平移与范数检查，float64分数差在1e-15量级。RoPE作用Q/K，本实现不旋转V。

## 54–56 分钟｜第18页：位置关系与可读范围

- 位置机制改变分数的数值关系，因果mask禁止读取未来，padding key mask禁止读取补齐项。
- 禁止位置设为−∞，softmax后权重为0；示意中最后一个key为pad，整列权重为0。
- pad query输出清零与loss忽略标签仍需各自处理；全屏蔽行需要避免softmax产生NaN。

**授课操作与提醒**：pipeline将上三角future和无效key位置做逻辑或，再把score设为-inf；不会修改token ID来实现mask。批中每句含bos/eos，至少有可见有效key；对全屏蔽行必须另作处理以免softmax NaN。padding query的输出最后清零，但训练损失仍需独立忽略padding标签。

## 56–58 分钟｜第19页：沿真实输入，把形状接起来

- tokenizer先生成离散ID，Embedding读取参数，线性层一次投影出Q/K/V。
- 把D=8拆成H=2个head，每头d_h=4；RoPE只处理Q/K，mask在scores上生效。
- softmax沿key维，再乘V并合并head；该脚本参数随机，未训练完整Block。

**授课操作与提醒**：运行input_pipeline.py，只跟踪形状与一行RoPE、一行mask。此分支不先加绝对PE，随机参数未训练；上面的bigram训练也没有Attention。明确两个实验各验证什么，避免把它们拼成已训练的大模型。首句实际token3个，加bos/eos为5，补到6；另一句4个token，加标记为6。

## 58–60 分钟｜第20页：用三个问题，检查是否理解

- 编码：按冻结merges逐步执行，重叠候选选择最小rank。
- 反传：同一ID在不同位置的向量梯度相加；padding lookup有专门约定。
- 位置与mask：前者描述位置关系，后者限制哪些key可读，二者互不替代。

**授课操作与提醒**：答案：重叠候选选最小rank；按各位置上游梯度求和，不是简单覆盖；旋转编码位置关系，mask决定哪些关系可读取。作业增加一个权重绑定实验，观察输出路径使更多embedding行获得梯度。完整答案及检查在exercises.md，保留数据与机制来源。

## 节奏与验收

课堂逐项走完第3页的权重计数、第4页的编码轨迹、第7页的查表和第16页的二维旋转。库组件定义可课前运行，现场主要核对关键语句与输出。

讲CE时允许先使用“预测概率减正确类别”这个结论，再用三类算例和autograd核对；不临时展开完整softmax Jacobian。重复ID的梯度一般要加实际向量，不能只数出现次数。

最低验收：解释rank为何优先；算清重复行梯度；说明RoPE的相对位移与mask各做什么。权重绑定、条件熵下界及长上下文泛化留作追问。bigram训练与随机Attention接口各自验证一部分机制，不能拼称为训练好的Transformer。
