# Class 1 简明版教师讲稿：60 分钟，三个问题

**对象**：会一点 Python、没学过深度学习的同学。整节课使用“我 喜欢 喝”这个前文。

核心问题：文字怎么变成数字？Attention 怎么混合上下文？混合后的向量怎么变成下一 token 的概率？每一步按“先猜输入和输出 → 运行 → 解释变化”讲解。

课堂代码采用人工参数，只算一个位置的单头 Attention 和一次候选选择。它不训练，也没有完整实现 Transformer。完整架构在后半段对照图认识，训练实现保留到后续课程。

## 课前只准备三样

1. 打开 [16 页简明版 PPT](class1_simple.pptx)，切到讲者备注。
2. 打开 [demo.ipynb](demo.ipynb)，选好 Python 内核。准备单元 0 定义 Softmax，单元 1–5 是三个教学步骤。
3. 打开 [一页课程地图](course_map.md)，旁边留一张纸给同学画流程。

先运行一次 `python3 class1/code/lesson.py` 和 `python3 class1/code/mask_demo.py`。脚本只需要 Python 标准库，课堂不安装依赖。Notebook 若不能运行，直接使用脚本和 [真实输出备份](sample_run.md)。

## 0–6 分钟｜补词开场，先给一张地图（PPT 1–2）

**0–3 分钟，第 1 页**：问“我喜欢喝____，你会填什么？”让同学给两个答案，追问为什么不是随便一个词。

承接：“模型也会利用前文计算候选的概率。今天用一组很小的数字，亲自算出其中一步。”说明同一前文会一直用到课尾，不会突然换成另一个例子。

**3–6 分钟，第 2 页**：只展示三段：文字变数字、混合上下文、选择下一项。让同学说说 Python 的列表和查字典，不预设其已学过线性代数。

此时运行 Notebook 准备单元 0，先把 `softmax()` 当作“分数变比例”的短函数；到第 29 分钟再展开。不要在开场引入梯度、多头或四维张量。

## 6–16 分钟｜① 文字变数字（PPT 3–5，单元 1）

**6–9 分钟，第 3 页**：展示 `text.split()`，得到 `['我','喜欢','喝']`。查 `vocab` 得到 `[0,1,2]`。

提问：“ID=2 就比 ID=0 更重要吗？”预期：不是，只是编号。真实 tokenizer 的单位可能是子词等，本课用空格切分是为了读起来直观。

**9–13 分钟，第 4 页**：把三个编号换成三个数字列表：

```text
我   → 0 → [1,0]
喜欢 → 1 → [0,1]
喝   → 2 → [1,1]
```

运行单元 1，逐行对照 token、ID、向量。向量就是数字列表，本课每个向量两个数字。这里的 embedding 表由我们人工设置；真实模型会训练更新它，不要给每一维指定固定语义。

**13–16 分钟，第 5 页**：解释词序也有意义，实际模型会引入位置信息。本课代码省略位置机制，先聚焦一个位置怎样混合上下文。

验收：“编号是什么？向量又是什么？”同学能区分即可进入第二段。

## 16–38 分钟｜② 先懂加权，再算权重（PPT 6–10，单元 2–4）

**16–20 分钟，第 6 页**：先给三个比例 `[0.2,0.3,0.5]`，对相同的三个向量加权：

```text
第一维：0.2×1 + 0.3×0 + 0.5×1 = 0.7
第二维：0.2×0 + 0.3×1 + 0.5×1 = 0.8
```

请同学算其中一维。这三个比例只为解释加权混合，下一步才计算实际演示权重。先理解权重用来做什么，再问它从哪里来。

**20–24 分钟，第 7 页，运行单元 2**：从“喝”这个位置出发，Q 是 `[1,1]`，三个 K 用来匹配，三个 V 用来提供信息。本例 Q/K/V 用恒等投影，数字相同、角色不同；实际模型通常分别学习三个投影。

只算当前“喝”的一行，不铺开全矩阵。板书：“Q/K 决定权重；V 提供被混合的信息。”

**24–29 分钟，第 8 页**：逐项相乘再相加，计算 Q 与三个 K 的点积，得到 `[1,1,2]`。除以 √2 后约为 `[0.707,0.707,1.414]`。2 来自本例向量维度，缩放用于控制分数尺度，不推导方差。

请同学手算第三项，读清循环是在对每个 key 重复相同操作。分数不是概率，也不要求总和为 1。

**29–33 分钟，第 9 页，运行单元 3**：Softmax 把分数变成比例。回到准备单元，解释先取 exp，再除以总和；减去最大值用于数值稳定，不改变最终比例。

得到约 `[0.248,0.248,0.503]`。第三个数大只是人工向量计算的结果，不能用来宣称真实模型认为什么词最重要。显示值经过四舍五入，三个数相加可能为 0.999，完整精度下和为 1。

**33–38 分钟，第 10 页，运行单元 4**：从 `mixed=[0,0]` 开始，循环累计每个位置贡献的两个数字，输出约 `[0.752,0.752]`。

提问：“现在出来的是‘酒’，还是一个向量？”预期：向量。若时间够，运行 Notebook 改 V 小实验：只把第三个 V 改成 `[3,1]`，新输出约 `[1.759,0.752]`，权重不变。必须新建 `changed_values`，不要原地改共享的 `values`，否则 K 也会一起变。

## 38–42 分钟｜因果遮罩：只看第一行（PPT 11）

本例计算最后一个已知输入位置，所以“喝”可以读取三个已给出的 token。

换成训练时的第一个位置，它不能看到后面的答案。把未来分数设为负无穷，再做 Softmax：

```text
[0.707, −∞, −∞] → [1,0,0]
```

运行 Notebook 遮罩单元，或 `python3 class1/code/mask_demo.py`。问为什么对角线可以保留：当前 token 已知，目标是预测下一个 token。

无需增加上三角矩阵、batch、头数等知识。只确认“未来位置贡献必须为零”。

## 42–50 分钟｜③ 输出向量怎样选词（PPT 12–13，单元 5）

**42–46 分钟，第 12 页**：用人工输出投影 `[2*mixed[0], mixed[1]]`，得到“酒、牛奶”的分数约 `[1.503,0.752]`，再 Softmax 得到约 `[0.680,0.320]`。

系数 2 是我们手动设置，不是训练结果。真实模型对整个词表输出 logits，本例仅在两个候选间归一化。完整模型在其余 Block 组件之后做输出映射，本例跳过这些组件来展示接口。

一定区分两次 Softmax：前一次给**输入位置**分配权重，用于混合；后一次给**输出候选**分配概率，用于选择。

**46–50 分钟，第 13 页，运行单元 5**：贪心选概率最高的“酒”，前文变成“我 喜欢 喝 酒”。问：“若再预测一次，输入会变成什么？”

实际生成重复这种预测，在结束标记或长度条件满足时停止。课堂脚本只展示一次选择，没有训练和生成循环，不把它说成能写整段回复的完整模型。

## 50–57 分钟｜放回真实架构，区分训练与生成（PPT 14–15）

**50–54 分钟，第 14 页**：对着图指出本课算过哪段、真实模型还包含什么：位置信息；Attention 混合；FFN 逐位置加工；残差和归一化帮助训练；Block 可以叠多层；最终归一化和输出映射得到整个词表的分数。

本课选择文本生成常用的 decoder-only 主线。原始 Transformer 是 Encoder–Decoder，decoder 还有读取 encoder 输出的 cross-attention。只说明差异，不展开新的计算。

**54–57 分钟，第 15 页**：这些数字从哪里来？课堂脚本手动设置；真实训练用句子的正确后续和误差学习 embedding、投影和网络参数。生成不更新参数，变化的是上下文。

如果同学理解顺畅，老师可在这个时段运行 `python class1/optional/tiny_transformer.py --steps 200`，只展示 loss 与生成结果，替代部分口头讲解。依赖提前装好，不读训练源码。拓展语料仍使用“茶、牛奶”等词，与主线人工示例是两套参数，不能混称；八句训练数据上的误差下降也不能说明泛化。

## 57–60 分钟｜同学自己讲一遍（PPT 16）

请同学画：`文字 → ID → 向量 → 权重与混合 → 候选分数 → 概率 → 下一 token`。

问三个问题：ID 与向量有何区别？Attention 为什么还没直接输出一个词？只改 V 会改变什么？答案见 [exercise_answers.md](exercise_answers.md)。再确认：只有训练才更新参数。

课后任务约 15 分钟：画链路、解释两次 Softmax、做一次只改 V 的实验。做到“先写预测、再运行、再解释”，无需重写完整模型。

## 时间与现场预案

| 情况 | 处理 |

| Python 列表推导式不熟 | 读成“逐个查表再放回列表”，不新增语法课程 |
| 不懂矩阵乘法 | 本课只算一个 query 和两个数字，不引入整矩阵公式 |

| 前半段超时 | 略去改 V 的现场实验，保留加权计算、候选选择与最终检查 |
